# zh-tw-writing

一個給 [Claude Code](https://claude.com/claude-code) 用的 skill，讓 Claude 寫出來的繁體中文報告讀起來像台灣人自然寫的正式中文，而不是一眼就看得出來的 AI 腔或翻譯腔。

它專注在中文寫作與改寫，順帶處理標點、中英空格這類文字排版細節，不負責整份文件的版面設計。

目前版本：v1.1.0，各版本的改動見[版本紀錄](#版本紀錄)。

## 為什麼需要它

請 AI 寫中文報告，常常會拿到這樣的文字：

> 值得注意的是，Microsoft在2023年首次公開這個組織。它是國家支持的駭客組織。它的目標是關鍵基礎設施。它主要使用系統內建工具；很難被偵測——防禦方必須從行為下手。

每句話都沒錯，讀起來卻一頓一頓的，句號太多，開頭是套話，中英文黏在一起，還混著分號和破折號。用了這個 skill 之後，同一段會寫成一個完整的句子，主語接續前文，因果關係也用「由於…因此」明確串起來：

> Microsoft 在 2023 年首次公開這個國家支持的駭客組織，它的攻擊目標是關鍵基礎設施，主要使用系統內建工具，由於很難被偵測，因此防禦方必須從行為下手。

這些規則都是實際寫作業報告時一條一條被挑出來的問題，不是憑空列的清單，每條規則也寫明了原因，讓 Claude 知道為什麼要這樣寫，遇到規則沒涵蓋的情況也能自己判斷。

## 功能

| 面向 | 內容 |
|---|---|
| 句子節奏 | 報告類長文平均每個句號前約 2.8 到 4 個逗號（參考範圍，說明文件、講稿等其他文體另外判斷），目標是少用句號，不是多加逗號，句子長短要有變化，省略主語的分句和前文留在同一句，關聯詞也可以像「由於…因此」一樣成對使用 |
| 去除 AI 腔 | 套話分成三級，「綜上所述」這類空話出現就改，「此外」這類正常連接詞只有密集出現才提醒，「研究顯示」沒附來源就要補上或刪除，另外整理了故作深刻的格言、硬湊三項這類查詞抓不到的結構型問題，附改寫前後與保留的例子 |
| 不要誤傷 | 引文、標題、真正的步驟順序、正式公文用語都保留，也不會為了不像 AI 而把正式文件改成口語 |
| 忠實原文 | 潤稿和翻譯只改說法，不新增事實，也不把「可能」改成「確定」，改別人的文件時數字、日期、引文一字不動 |
| 中英文與標點 | 依《中文文案排版指北》與教育部標點符號手冊，中英文與數字之間加半形空格，引號用「」，並列用頓號，破折號寫成「──」，外國人名的間隔號用「．」，統計數字與日期依行政院原則用阿拉伯數字 |
| 台灣用語 | 45 組直接替換的兩岸用語，加上「文件」「數據」這類要看語意判斷的詞，避免把台灣的正常用法也改掉 |
| 英翻中 | 保留原文的確定程度（may 是「可能」，不是「會」），專有名詞第一次出現寫成「中譯（English）」，並附常見翻譯腔的改法 |
| 字型 | 預設 Noto Sans TC，附 HTML、PDF、Word 的設定方式 |
| 檢查腳本 | 一個指令檢查句子節奏、AI 腔、標點與台灣用語，還能自動補上中英空格 |

逗號比例不是隨便訂的，我們拿台灣的中文文章實測過，中文維基百科約每句 1.5 個逗號，iThome 資安新聞約 3.3 個，報告文體適合落在新聞這一側。

## 什麼時候會用到

這個 skill 只在產出正式中文文件時觸發，平常的中文對話不會套用這些規則，常見情境整理如下。

| 情境 | 會不會觸發 |
|---|---|
| 寫作業報告、論文段落、企劃書、正式信件、說明文件 | 會 |
| 潤稿、校對，或把中文 HTML、PDF、Word 排得好讀 | 會 |
| 把英文文章或報告翻成繁體中文 | 會 |
| 一般問答，即使 Claude 用中文長篇回答 | 不會 |
| 中文翻成英文、程式碼與註解、commit 訊息、簡體中文內容 | 不會 |

## 安裝

依照你使用 Claude 的方式，選擇下面其中一種。

### Cowork、Claude 桌面版與 claude.ai

不需要用到指令，下載 zip 後上傳即可。

1. 下載 [zh-tw-writing.zip](https://github.com/LCY000/zh-tw-writing/releases/latest/download/zh-tw-writing.zip)，不用解壓縮。
2. 開啟「設定 → 功能（Capabilities）」，確認「程式碼執行與檔案建立」已開啟，檢查腳本才能執行。
3. 在同一頁的「技能（Skills）」上傳剛才下載的 zip。

上傳後，在 Cowork 或一般對話中產出正式中文文件時就會自動套用。之後有新版本時，下載新的 zip 重新上傳即可，歷次版本都列在 [Releases](https://github.com/LCY000/zh-tw-writing/releases) 頁面。

### Claude Code

```bash
git clone https://github.com/LCY000/zh-tw-writing.git
ln -s "$(pwd)/zh-tw-writing/zh-tw-writing" ~/.claude/skills/zh-tw-writing
```

用捷徑安裝的好處是之後只要在 clone 下來的資料夾執行 `git pull`，就會更新到最新版。如果不想用捷徑，也可以直接把 `zh-tw-writing/zh-tw-writing` 資料夾複製到 `~/.claude/skills/` 底下，重新開一個 Claude Code 對話就會生效。

### 自己打包 zip

修改過內容、想上傳自己的版本時，在專案根目錄執行以下指令。zip 解開後最上層必須是 `zh-tw-writing` 資料夾，裡面直接放 `SKILL.md`。

```bash
zip -r zh-tw-writing.zip zh-tw-writing -x "*/__pycache__/*" "*.DS_Store"
```

## 檢查腳本

寫好或改好中文文件之後，可以自己跑一次檢查。腳本只需要 Python 3，不用安裝其他套件，支援 `.html`、`.md`、`.txt`，統計時會自動略過表格、標題、程式碼與英文參考文獻，HTML 只統計 `<p>` 與 `<li>` 裡的文字。「」『』裡的引文與《》〈〉裡的標題不列入套話與用語檢查，引文仍會算進句子節奏，但引文中間的句號不另外斷句。檢查結果只是提醒，數字略微超出範圍但讀起來順暢，就不用硬改。

```bash
python3 zh-tw-writing/scripts/check_zh.py 報告.md                  # 只檢查
python3 zh-tw-writing/scripts/check_zh.py 報告.md --fix-spacing    # 自動補中英空格，原檔備份為 .bak，不會改到程式碼
python3 zh-tw-writing/scripts/check_zh.py 報告.html --min 2.5 --max 4.5   # 調整建議範圍
```

拿上面「改寫前」那段文字檢查，會得到這樣的結果（節錄）：

```text
【句子節奏】
句號 4、逗號 1，平均每句逗號 0.25（建議 2.8–4，以報告類長文為準）→ 偏低：句子可能太碎，可考慮合併同主題短句

連續 3 句以上無逗號的短句（1 處）：
   它是國家支持的駭客組織。 / 它的目標是關鍵基礎設施。 / 它主要使用系統內建工具；很難被偵測——防禦方

【AI 腔】
強提示（出現一次就該改）（1 處）：
   空泛轉折「值得注意的是」：…值得注意的是，Microsoft在2023年…

【標點】
分號（並列的條列項目可以用，其他多半改成逗號或句號）（1 處）：
   …基礎設施。它主要使用系統內建工具；很難被偵測——防禦方必須從行為下…

破折號寫法不對（教育部手冊寫成兩格的──）（1 處）：
   …主要使用系統內建工具；很難被偵測——防禦方必須從行為下手。…

中英文或數字沒有空格（% 與 ° 後面接中文也要空格）（2 處）：
   …值得注意的是，Microsoft在2023年首次公開這個組織。它是…
```

改寫後的那段，逗號比例落在範圍內，腳本只會提醒「因此」「關鍵」兩個弱提示出現在同一個短段落。這裡的「關鍵」是專有名詞「關鍵基礎設施」的一部分，「因此」是成對的關聯詞，兩個都不用改。弱提示只是提醒，要回到句子裡判斷，不要看到就刪。

## 檔案結構

```text
zh-tw-writing/
├── README.md
└── zh-tw-writing/
    ├── SKILL.md              # 給 Claude 讀的寫作原則
    ├── references/
    │   ├── ai-phrases.md     # AI 腔用語清單，分三級
    │   ├── ai-patterns.md    # 查詞抓不到的結構型 AI 腔
    │   ├── terms.md          # 台灣用語、看語意的詞、翻譯腔
    │   └── fonts.md          # 產出 HTML、PDF、Word 時的字型設定
    └── scripts/
        └── check_zh.py       # 檢查腳本，直接讀取 references 裡的清單
```

## 參考資料

- [中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines)，中英文空格與全形標點的規則來源
- [教育部《重訂標點符號手冊》修訂版](https://language.moe.gov.tw/001/Upload/FILES/SITE_CONTENT/M0001/HAU/Revised_Handbook_of_Punctuation.pdf)，逗號、頓號、引號、書名號、破折號、間隔號等標點規則的依據
- [行政院《公文書橫式書寫數字使用原則》](https://www.ey.gov.tw/File/9AAF90C72F253EA?A=C)，收錄於行政院法規會《行政機關法制作業實務》（2025 年版），統計數字、日期用阿拉伯數字的依據
- [吳佳容（2013）《華語第三人稱回指分析——以母語者與英、日語背景學習者為例》](https://etds.lib.ntnu.edu.tw/thesis/detail/7161f0f6fa748b9189f51b973a92500f)，國立臺灣師範大學華語文教學研究所碩士論文，「省略主語的分句留在同一句」的依據，論文指出話題鏈以句號為界，省略主語主要發生在話題鏈內
- [Noto Sans TC](https://fonts.google.com/noto/specimen/Noto+Sans+TC)，預設字型

## 致謝

這個 skill 在改版時參考了以下專案，每一項都回到原始檔確認過，所有內容都經過重新整理與改寫，以符合台灣正式文件的需求：

- [blader/humanizer](https://github.com/blader/humanizer)：套話分成強弱等級，強的看到一次就改，弱的要搭配其他特徵才算，以及不得新增原文沒有的事實、句子長短要交錯，還有格言、反方辯論、硬湊三項、限定詞堆疊這類結構型模式。
- [kevintsai1202/humanizer-zh-tw](https://github.com/kevintsai1202/humanizer-zh-tw)：結構型模式用「改寫前、改寫後、保留」三段範例說明的寫法，以及資訊缺口不能用猜測補上。
- [Nanako0129/sepia](https://github.com/Nanako0129/sepia)：依教育部手冊的破折號「──」、間隔號「．」與引號內句尾標點，統計數字用阿拉伯數字，「和」不要用來把兩件完整的事接起來，以及台灣新聞語料中三項列舉、單用「此外」「然而」都屬常態的實測數據。
- [op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh)：改稿時保留原文的資訊與確定程度，不增加原文沒有的事實、數字與來源。
- [jiji262/humanizer-chinese](https://github.com/jiji262/humanizer-chinese)：時代開場、升華結尾這類套話的分類，頓號與半形標點的檢查，以及公文、技術文件不要改成口語。
- [acchuang/zh-tw-humanizer](https://github.com/acchuang/zh-tw-humanizer)：修改他人文件時，數字、日期、引文要列入保護清單，一字不改。
- [tentenco/shuorenhua-zh-tw](https://github.com/tentenco/shuorenhua-zh-tw)：依教育部《重訂標點符號手冊》整理的標點用法，包括頓號、『』、《》、〈〉與刪節號。
- [leoluyi/skills](https://github.com/leoluyi/skills)：翻譯腔的實例，分號用於並列職責的寫法，以及「數據」在統計語境中可以保留。

## 版本紀錄

### v1.1.0（2026-10-21）

- 新增 `references/ai-patterns.md`，整理六種查詞抓不到的結構型 AI 腔：故作深刻的格言、跟不存在的反方辯論、硬湊三項、限定詞堆疊、文章在談論自己、資訊缺口的處理，每種都附改寫前後與保留的例子。
- AI 腔清單新增「宣傳語」「對讀者喊話」兩類，並說明清單是例子，同一類的其他說法也要處理，「中國流行語」除外。
- 破折號改用教育部手冊的「──」，成對夾注算一組，單一的「—」是表示起訖的連接號。
- 新增間隔號「．」、引號內句尾標點、統計數字用阿拉伯數字三條規則。
- 翻譯腔新增「和」「與」把兩件完整的事接起來的寫法。
- 逗號比例註明以報告類長文為準，其他文體另外判斷。
- 字型設定移到 `references/fonts.md`，只在產出 HTML、PDF、Word 時讀取。
- 專有名詞的寫法原本在 `SKILL.md` 與 `terms.md` 各寫一次，現在只留在 `SKILL.md` 第六節。
- 檢查腳本：書名號裡的標題不再誤報，引文中間的句號不另外斷句，補抓「――」「--」與單一的「─」，新增間隔號檢查，HTML 的大寫 `<BODY>` 也能正確辨認。
