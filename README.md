# zh-tw-writing

zh-tw-writing 是用來優化中文寫作方面的 skill，讓 AI 寫出來的中文報告，看起來像是台灣人寫的正式中文，不要讓人一眼就看出文章裡有 AI 腔和翻譯腔。

這些規則是使用 Claude 寫報告時，針對它實際寫出來的問題一條一條整理出來的，所以主要以 Claude 為對象。但 skill 採用通用的 Agent Skills 格式，Codex 與 ChatGPT 也能直接安裝使用，不用修改任何檔案，安裝方式見[安裝](#安裝)。

zh-tw-writing 涵蓋中文寫作、潤稿與英翻中，從句子節奏、AI 腔、台灣用語到標點與中英空格都會處理，改寫時也會守住原文的事實，並附一支檢查腳本。整份文件的版面設計不在範圍內。

目前版本：v1.3.0，各版本的改動見[版本紀錄](#版本紀錄)。

## 為什麼需要它

請 AI 寫中文報告，常常會拿到這樣的文字：

> 值得注意的是，Microsoft在2023年首次公開這個組織。它是國家支持的駭客組織。它的目標是關鍵基礎設施。它主要使用系統內建工具；很難被偵測——防禦方必須從行為下手。

每句話都沒錯，讀起來卻一頓一頓的，句號太多，開頭是套話，中英文黏在一起，還混著分號和破折號。用了這個 skill 之後，同一段會寫成一個完整的句子，主語接續前文，因果關係也用「由於…因此」明確串起來：

> Microsoft 在 2023 年首次公開這個國家支持的駭客組織，該組織以關鍵基礎設施為目標，主要使用系統內建工具，由於很難被偵測，因此防禦方必須從行為下手。

每條規則都寫明了原因，讓 AI 知道為什麼要這樣寫，遇到規則沒涵蓋的情況也能自己判斷。

逗號比例是拿台灣的中文文章實測訂出來的，中文維基百科約每句 1.5 個逗號，iThome 資安新聞約 3.3 個，報告文體適合落在新聞這一側。

## 什麼時候會用到

這個 skill 只在產出正式中文文件時觸發，平常的中文對話不會套用這些規則，常見情境整理如下。

| 情境 | 會不會觸發 |
|---|---|
| 寫作業報告、論文段落、企劃書、正式信件、說明文件 | 會 |
| 潤稿、校對，或把中文 HTML、PDF、Word 排得好讀 | 會 |
| 把英文文章或報告翻成繁體中文 | 會 |
| 一般問答，即使 AI 用中文長篇回答 | 不會 |
| 中文翻成英文、程式碼與註解、commit 訊息、簡體中文內容 | 不會 |

## 安裝

Claude、Codex 與 ChatGPT 都支援 Agent Skills 格式，三邊安裝的是同一份檔案，依照你使用的工具選擇下面其中一種。

### Claude 桌面版與 claude.ai

不需要用到指令，下載 zip 後上傳即可。

1. 下載 [zh-tw-writing.zip](https://github.com/LCY000/zh-tw-writing/releases/latest/download/zh-tw-writing.zip)，不用解壓縮。
2. 開啟「設定 → 功能（Capabilities）」，確認「程式碼執行與檔案建立」已開啟，檢查腳本才能執行。
3. 在同一頁的「技能（Skills）」上傳剛才下載的 zip。

上傳後，在對話中產出正式中文文件時就會自動套用。之後有新版本時，下載新的 zip 重新上傳即可，歷次版本都列在 [Releases](https://github.com/LCY000/zh-tw-writing/releases) 頁面。

### Claude Code 與 Codex

直接請 AI 幫你裝就好，把下面這段話貼給 Claude Code 或 Codex（CLI、Codex app、IDE 擴充套件都可以）：

```text
請幫我安裝這個 skill：https://github.com/LCY000/zh-tw-writing ，安裝方式照 README 的說明。
```

AI 會讀這份 README，先問你要把 skill 裝在哪裡，沒有特別偏好的話回答「你決定」，它就會照建議的位置裝好。裝好後如果沒有生效，重新開一個對話即可。

<details>
<summary>安裝步驟（給 AI 參考，也可以自己照著做）</summary>

**安裝前先用一個問題確認使用者的偏好**，每一項都附上建議的預設值，使用者說「你決定」或沒有特別偏好時，就照預設安裝，不要一項一項分開追問：

1. repo 要放在哪裡：預設 clone 到 `~/skills/zh-tw-writing`，再用捷徑連到 skill 資料夾，之後在那裡執行 `git pull` 就能更新。也可以放在使用者指定的資料夾，或是不 clone、只把 skill 資料夾複製過去，這樣最簡單，但之後更新要重新下載。
2. 安裝範圍：預設裝在使用者層級，所有專案都能用。只想在目前專案使用時，改放到專案裡的 `.claude/skills/`（Claude Code）或 `.agents/skills/`（Codex）。
3. 使用者如果也在用另一個工具（Claude Code 或 Codex），要不要一起裝，兩邊可以共用同一份 clone。

預設的安裝指令如下：

```bash
git clone https://github.com/LCY000/zh-tw-writing.git ~/skills/zh-tw-writing

# Claude Code
mkdir -p ~/.claude/skills
ln -s ~/skills/zh-tw-writing/zh-tw-writing ~/.claude/skills/zh-tw-writing

# Codex
mkdir -p ~/.agents/skills
ln -s ~/skills/zh-tw-writing/zh-tw-writing ~/.agents/skills/zh-tw-writing
```

捷徑要指向 repo 裡面那層 `zh-tw-writing/` 資料夾，也就是 `SKILL.md` 所在的位置，不是 repo 本身。目標位置已經有 `zh-tw-writing` 時，先告訴使用者，不要直接覆蓋。裝好後回報安裝位置與更新方式。

### ChatGPT

ChatGPT 目前要請工作模式裡的 Skill Creator 代為安裝，不能直接選檔上傳。

1. 下載 [zh-tw-writing.zip](https://github.com/LCY000/zh-tw-writing/releases/latest/download/zh-tw-writing.zip)，不用解壓縮。
2. 在「外掛程式」頁面選「新增 → 新增 skill」，畫面會切換到工作模式，輸入框裡已經帶入 Skill Creator。
3. 點輸入框左下角的「＋」附上 zip，請它直接安裝，例如：「這是已經做好的 skill，請不要重新設計，檢查 zip 內容後直接幫我安裝。」

### 自己打包 zip

修改過內容、想上傳自己的版本時，在專案根目錄執行以下指令。zip 解開後最上層必須是 `zh-tw-writing` 資料夾，裡面直接放 `SKILL.md`。測試檔是維護用的，不放進 zip。

```bash
zip -r zh-tw-writing.zip zh-tw-writing -x "*/__pycache__/*" "*.DS_Store" "zh-tw-writing/scripts/tests/*"
```

## 檢查腳本

寫好或改好中文文件之後，可以自己跑一次檢查。腳本只需要 Python 3，不用安裝其他套件，支援 `.html`、`.md`、`.txt`。

- 句子節奏只看內文段落，表格、標題與圖說本來就短，不列入。AI 腔、標點與台灣用語看所有可見文字，表格和圖說裡的用語一樣會被抓到。
- 程式碼、Markdown 的 YAML frontmatter 與英文參考文獻不檢查。HTML 另外略過 `<nav>` 與 class 或 id 含 `toc`、`mono` 的元素，並顯示檢查了多少比例的可見文字。
- 「」『』裡的引文與《》〈〉裡的標題不列入套話與用語檢查，引文仍會算進句子節奏，但引文中間的句號不另外斷句。
- Markdown 的 `>` 引用區塊、HTML 的 `<blockquote>` 與圖片整段略過。
- 每則提醒都附命中那一行的行號與所屬章節。有章節標題時會列出各節的逗號比例，並標出偏離建議範圍的節，另外列出比例最低的段落，方便找到要改的地方。同一類提醒太多時，前幾處附前後文，其餘列出行號。
- 輸出的第一行是各類提醒的總數，細節在後面。一次給好幾個檔案或一個資料夾時，開頭先列各檔案的總數，再逐檔報告，最後印全部的合計，報告拆成封面、內文、附錄幾個檔案時，漏掉哪個一眼就看得出來。
- 【痕跡】列出看不見的字元（零寬空格、不換行空格）、AI 工具留下的引用標記與網址參數（`[cite: 1]`、`utm_source=chatgpt.com`），以及沒填的佔位文字（「【請在此處填寫】」「TBD」）。
- 加上 `--source 原稿` 時，列出原稿有、改寫稿比較少，以及改寫稿多出來的數字、日期、網址、代碼、版本號與引文。潤稿時比原文寫法，3,200 改成 3200 也會報。原稿是英文時當成英翻中，日期與「350 萬」「3.5 million」這類寫法換算後再比。

檢查結果只是提醒，數字略微超出範圍但讀起來順暢，就不用硬改。

```bash
python3 zh-tw-writing/scripts/check_zh.py 報告.md                  # 只檢查
python3 zh-tw-writing/scripts/check_zh.py 封面.html 內文.html 附錄.html   # 一次檢查多個檔案，最後印出合計
python3 zh-tw-writing/scripts/check_zh.py report/                  # 檢查資料夾裡的 .html、.htm、.md、.txt（不含子資料夾）
python3 zh-tw-writing/scripts/check_zh.py 譯文.md --source 原文.md   # 比對原稿的數字、網址、引文有沒有遺失或新增
python3 zh-tw-writing/scripts/check_zh.py 報告.md --fix-spacing    # 自動補中英空格，原檔備份為 .bak，不會改到程式碼
python3 zh-tw-writing/scripts/check_zh.py 報告.html --min 2.5 --max 4.5   # 調整建議範圍
```

拿〈為什麼需要它〉第一段範例（用 skill 之前的那段）檢查，會得到這樣的結果（節錄）：

```text
總數：逗號比例 0.25（偏低）｜句子節奏 2（比例偏低的段落 1、連續短句 1）｜AI 腔 1（強提示 1）｜標點 4（分號 1、破折號寫法 1、中英空格 2）｜台灣用語 1（需確認用語 1）｜痕跡 0

【句子節奏】
句號 4、逗號 1，平均每句逗號 0.25（建議 2.8–4，以報告類長文為準）→ 偏低：句子可能太碎，可考慮合併同主題短句

連續 3 句以上無逗號的短句（1 處）：
   第 1 行：它是國家支持的駭客組織。 / 它的目標是關鍵基礎設施。 / 它主要使用系統內建工具；很難被偵測——防禦方

【AI 腔】
強提示（出現一次就該改）（1 處）：
   空泛轉折「值得注意的是」：第 1 行：…值得注意的是，Microsoft在2023年…

【標點】
分號（自己寫的內文不用分號，重寫整句：短的並列用逗號，其中一項有逗號時把短的放前面，或把細節移到下一句，不要拆成一句一句的短句。引文裡的照原文，不列入）（1 處）：
   第 1 行：…基礎設施。它主要使用系統內建工具；很難被偵測——防禦方必須從行為下…

破折號寫法不對（教育部手冊寫成兩格的──）（1 處）：
   第 1 行：…主要使用系統內建工具；很難被偵測——防禦方必須從行為下手。…

中英文或數字沒有空格（% 與 ° 後面接中文也要空格）（2 處）：
   第 1 行：…值得注意的是，Microsoft在2023年首次公開這個組織。它是…

【台灣用語】
需要看語意確認的詞（對照 references/terms.md「看語意判斷」，每一處都要回到句子判斷，不要一律替換）：
   「支持」1 處：
      第 1 行：…次公開這個組織。它是國家支持的駭客組織。它的目標是關…
```

「國家支持的駭客組織」的「支持」是台灣的正常用法，不是技術支援的意思，所以不用改，這就是「看語意確認」的詞要回到句子判斷的原因。

改寫後的那段，逗號比例落在範圍內，「支持」一樣會列出來，另外只會提醒「因此」「關鍵」兩個弱提示出現在同一個短段落。這裡的「關鍵」是專有名詞「關鍵基礎設施」的一部分，「因此」是成對的關聯詞，兩個都不用改。弱提示只是提醒，要回到句子裡判斷，不要看到就刪。

## 檔案結構

```text
zh-tw-writing/
├── README.md
├── CHANGELOG.md              # 每一版的詳細改動，給維護者看
├── LICENSE、NOTICE           # 授權條款與作者資訊
├── zh-tw-writing/
│   ├── SKILL.md              # 給 AI 讀的寫作原則
│   ├── LICENSE、NOTICE       # 和根目錄的相同，讓 zip 也帶著授權
│   ├── references/
│   │   ├── ai-phrases.md     # AI 腔用語清單，分三級
│   │   ├── ai-patterns.md    # 查詞抓不到的結構型 AI 腔（寫或改文件前必讀）
│   │   ├── translation-traps.md  # 翻譯腔與簡轉繁的陷阱（寫或改文件前必讀）
│   │   ├── terms.md          # 台灣用語、看語意的詞、字形
│   │   └── fonts.md          # 產出 HTML、PDF、Word 時的字型設定
│   └── scripts/
│       ├── check_zh.py       # 檢查腳本，直接讀取 references 裡的清單
│       └── tests/            # 檢查腳本的回歸測試，修改 skill 時用
└── evals/                    # 行為 eval：比較 AI 有、沒有 skill 時的產出，修改 skill 時用
```

## 修改這個 skill

改了 `check_zh.py` 或 `references/` 裡的清單之後，先跑一次測試，全部通過才算改好：

```bash
python3 zh-tw-writing/scripts/tests/run_tests.py       # 加 -v 會印出失敗題目的完整輸出
```

每一題是一小段文字，寫好「應該抓到」與「不應該抓到」的提醒。`run_tests.py` 裡的題目是維護者寫的，`cases_claude.py` 與 `cases_codex.py` 是另外請 Claude 與 Codex 的子代理只看規範、不看程式寫的，避免自己寫程式又自己出考題。修好一個誤報或漏抓時，把那句加進 `run_tests.py`，之後就不會再犯。

測試只確認腳本有沒有改壞，SKILL.md 本身有沒有讓 AI 照規則寫，要用 `evals/` 的行為 eval 檢查。`evals/cases.json` 是 12 個正式文件案例（潤稿、英翻中、潤別人的信、從素材寫報告），每個案例讓 AI 在有、沒有 skill 時各寫一次，再用 `evals/grade.py` 檢查埋好的事實有沒有保留、有沒有中國用語與破折號誤用等，做法見 `evals/README.md`。

## 參考資料

- [中文文案排版指北](https://github.com/sparanoid/chinese-copywriting-guidelines)，中英文空格與全形標點的規則來源
- [教育部《重訂標點符號手冊》修訂版](https://language.moe.gov.tw/001/Upload/FILES/SITE_CONTENT/M0001/HAU/Revised_Handbook_of_Punctuation.pdf)，逗號、頓號、引號、書名號、破折號、間隔號等標點規則的依據
- [行政院《公文書橫式書寫數字使用原則》](https://www.ey.gov.tw/File/9AAF90C72F253EA?A=C)，收錄於行政院法規會《行政機關法制作業實務》（2025 年版），統計數字、日期用阿拉伯數字的依據
- [吳佳容（2013）《華語第三人稱回指分析——以母語者與英、日語背景學習者為例》](https://etds.lib.ntnu.edu.tw/thesis/detail/7161f0f6fa748b9189f51b973a92500f)，國立臺灣師範大學華語文教學研究所碩士論文，「省略主語的分句留在同一句」的依據，論文指出話題鏈以句號為界，省略主語主要發生在話題鏈內
- [台閩與中國大陸的計算機術語/用語對照表](https://hackmd.io/@SeanPeng/B1psY1s6K)，SeanPeng 整理，v1.2.0 擴充資訊領域用語時的主要來源，收錄時排除了台灣也常用的詞，以及原表有疑問的條目
- [Noto Sans TC](https://fonts.google.com/noto/specimen/Noto+Sans+TC)，預設字型

## 致謝

這個 skill 改版時參考了以下專案。列在這裡的每一項，都回頭讀過對方 repo 裡的原始檔案，不是憑印象或轉述，參考的內容也依台灣正式文件的需求重新整理、改寫過：

- [blader/humanizer](https://github.com/blader/humanizer)：套話分成強弱等級，強的看到一次就改，弱的要搭配其他特徵才算。另外也參考了它不得新增原文沒有的事實、句子長短要交錯的原則，以及格言、反方辯論、硬湊三項、限定詞堆疊這類結構型模式。
- [kevintsai1202/humanizer-zh-tw](https://github.com/kevintsai1202/humanizer-zh-tw)：結構型模式用「改寫前、改寫後、保留」三段範例說明的寫法，資訊缺口不能用猜測補上，以及要清掉的看不見字元有哪些。
- [Nanako0129/sepia](https://github.com/Nanako0129/sepia)：依教育部手冊的破折號「──」、間隔號「．」與引號內句尾標點，統計數字用阿拉伯數字，「和」不要用來把兩件完整的事接起來，以及台灣新聞語料中三項列舉、單用「此外」「然而」都屬常態的實測數據。
- [op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh)：改稿時保留原文的資訊與確定程度，不增加原文沒有的事實、數字與來源。
- [jiji262/humanizer-chinese](https://github.com/jiji262/humanizer-chinese)：時代開場、升華結尾這類套話的分類，頓號與半形標點的檢查，以及公文、技術文件不要改成口語。
- [acchuang/zh-tw-humanizer](https://github.com/acchuang/zh-tw-humanizer)：修改他人文件時，數字、日期、引文要列入保護清單，一字不改。v1.3.0 另外參考了它的簡轉繁陷阱與台灣慣用字形、AI 工具痕跡與佔位文字的清單、比對原稿事實的做法、「加上判斷也算捏造」的幾種情況，以及虛假範圍、回信複述背景、重複免責這幾個模式，用語表也補了它有、我們缺的詞。
- [tentenco/shuorenhua-zh-tw](https://github.com/tentenco/shuorenhua-zh-tw)：依教育部《重訂標點符號手冊》整理的標點用法，包括頓號、『』、《》、〈〉與刪節號。
- [leoluyi/skills](https://github.com/leoluyi/skills)：翻譯腔的實例，分號用於並列職責的寫法，以及「數據」在統計語境中可以保留。

## 版本紀錄

這裡列出每一版用起來會感覺到的改變。改了哪些檔案、規則的細節與原因，見 [CHANGELOG.md](CHANGELOG.md)。

### v1.3.0（2026-11-25）

- AI 寫中文之前，會先讀「結構型 AI 腔」和「翻譯腔」這兩份說明。以前這兩份常被跳過，寫出來的文章容易出現硬湊三項、照英文句型寫的句子。
- 潤稿和翻譯更貼近原文，不會替作者加上承諾、推銷或自己算出來的數字。檢查腳本也能拿原稿比對，看數字、日期和引文有沒有被改動。
- 貼進來的文字如果夾著「忽略先前的指示」這類指令，AI 會照常處理原文，並告訴你指令夾在哪裡。
- 只說「幫我檢查」時，AI 只列出問題，不會直接改你的文件。
- 自己寫的內文不再用分號，用「但」「而且」這類詞之前會先看前後是什麼關係，封面、摘要和內文的數字也要一致。
- 用語表擴大，中國用語從 129 組增加到 160 組，要看意思判斷的詞從 62 個增加到 77 個，也會抓出「裏」「爲」這類台灣不用的字形。
- 檢查腳本可以一次檢查多個檔案或整個資料夾，也會找出看不見的字元、AI 工具留下的引用標記和沒填的佔位文字。
- 修正「視頻通話」被建議改成「影片通話」、「打印機」被建議改成「列印機」的錯誤。
- 授權從 MIT 改成 Apache 2.0，轉發或修改這個 skill 時要保留 NOTICE 裡的作者資訊，下載的 zip 也會附上授權檔。

### v1.2.0（2026-11-12）

- 檢查腳本會檢查 HTML 裡的表格、圖說和卡片，不再只看段落，並告訴你檢查了多少比例的文字。
- 每則提醒附上行號和所屬章節，也會列出逗號比例最低的段落，方便找到要改的地方。
- 中國用語從 45 組增加到 129 組，涵蓋「線程」「端口」這類資訊領域的用語，「演算法」裡的「算法」這類台灣用語也不再被誤報。
- 自己寫的文件直接用台灣說法。潤稿別人的文件時，AI 會列出改了哪些詞，拿不準的留給你決定。
- 交給別人的文件不會留下版本沿革、AI 工具的運作細節，或讀者打不開的檔案路徑。
- AI 改完會重跑檢查並讀完整份結果，說某個提醒可以不改時要附上理由。

### v1.1.1（2026-10-23）

- 新增 Codex 和 ChatGPT 的安裝方式。
- Claude Code 和 Codex 改成把一段話貼給 AI，由 AI 讀 README 幫你安裝，裝之前會先問你要裝在哪裡。
- 寫作規則和檢查腳本沒有變動。

### v1.1.0（2026-10-21）

- 新增查詞抓不到的 AI 腔整理，例如故作深刻的格言、跟不存在的反方辯論、硬湊三項，每種都附改寫前後的例子。
- 套話清單新增宣傳語和對讀者喊話兩類，清單沒列到的同類說法也會處理。
- 標點改依教育部手冊，破折號寫成「──」，外國人名的間隔號用「．」，統計數字用阿拉伯數字。
- 逗號比例註明是報告類長文的標準，說明文件、講稿等其他文體另外判斷。
- 書名號裡的標題不再被誤報。

### v1.0.0（2026-10-11）

- 第一版，整理 Claude 寫中文報告時常見的問題，涵蓋句子節奏、AI 腔、忠實原文、中英混排、台灣用語、英翻中與字型。
- 以平均每個句號前約 2.8 到 4 個逗號為目標，讓 AI 少用句號，句子不會一頓一頓的。
- 套話分成三級，「綜上所述」出現就改，「此外」密集出現才提醒，「研究顯示」沒附來源要補上或刪除。
- 潤稿和翻譯只改說法，不新增事實，也不把「可能」改成「確定」。
- 收錄 45 組兩岸用語，加上「文件」「數據」這類要看意思判斷的詞。
- 附一支檢查腳本，檢查句子節奏、AI 腔、標點和台灣用語，也能自動補中英空格，不會改到 HTML 裡的程式碼和標籤。
