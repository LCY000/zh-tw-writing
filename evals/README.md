# 行為 eval

`scripts/tests/` 只檢查腳本有沒有改壞，這裡檢查的是 SKILL.md 本身：同一個案例讓 AI 在有 skill、沒有 skill 時各寫一次，看規則有沒有讓產出變好。

## 檔案

- `cases.json`：12 個正式文件案例，包括潤稿、英翻中、潤別人的信與從素材寫報告。案例由獨立的子代理只看規範寫成，內容都是虛構的。每個案例的欄位：
  - `instruction`、`input`：給 AI 的指示與原稿。
  - `must_keep`：產出裡一定要原樣出現的字串，例如數字、代碼、網址、引文。
  - `must_not`：出現就一定錯的字串，`re:` 開頭的是正規表示式。
  - `rules`：這個案例主要考 SKILL.md 的哪幾條。
  - `judge`：程式查不到、要人工或另一個模型評的重點，例如捏造的承諾、改過頭。
- `grade.py`：評分腳本，只用 Python 內建模組，會呼叫 `check_zh.py`。
- `runs/<日期>/`：每次執行的產出、評分結果（`grade.md`）與盲評結果（`judge.md`）。

## 怎麼跑

1. 印出每個案例的提示：

   ```bash
   python3 evals/grade.py --prompts
   ```

2. 每個案例在兩種條件下各產出一次，存成 `runs/<日期>/<案例 id>/<條件>.md`：
   - `with_skill`：AI 讀過 SKILL.md 並照著做，可以跑檢查腳本。
   - `without_skill`：不給 skill，只給同樣的提示。在 Claude Code 裡用子代理跑時，要明確告訴它不要讀 skill，因為 skill 裝在使用者層級會自動觸發。

   `.md` 檔只放要交出去的文件本身。給使用者的說明（改了哪些詞、原稿夾帶的指令）另外存成 `<條件>.notes.md`，不評分。同一個條件跑第二次時寫成 `with_skill-2.md`，合計時會併在一起。

3. 評分：

   ```bash
   python3 evals/grade.py evals/runs/<日期>
   ```

   每份產出列出有沒有缺 `must_keep`、有沒有出現 `must_not`，以及 `check_zh.py` 查到的中國用語、台灣不用的字形、強提示、破折號、半形標點、看不見的字元、工具痕跡、分號、「不是…而是…」與逗號比例。潤稿、英翻中與信件另外和原稿比對，列出新增與遺失的事實。前七類出現就算沒通過，後面幾類只列數量，要回到文件判斷。「遺失事實」有一部分是預期中的：刪掉回信裡複述對方來信的段落、刪掉原稿夾帶的指令，或把 (1)(2)(3) 改成編號清單，原稿的數字本來就會變少。

4. 程式查不到的部分，把 `judge` 欄、原稿與產出交給另一個模型或自己讀，判斷有沒有捏造、改變確定程度、改過頭。交給模型評時，把兩種條件的產出隨機標成 A、B，評審不知道哪一份有用 skill，評完再對照，結果存成 `runs/<日期>/judge.md`。

## 怎麼看結果

- 這裡的分數是比較用的，看有、沒有 skill 的差距，以及改版前後的變化，不是絕對的品質分數。
- 每個條件只跑一兩次，差一兩題可能只是隨機差異，要看每一份的細節，不要只看合計。
- 從素材自己寫的案例（write-*），推算本身不算錯。算錯、把不同類別併成一類，或讓推算看起來像素材給的數字才扣分。潤稿、翻譯與信件照 SKILL.md 第四節，替作者推算算是新增內容。
- 案例要新增或修改時，同樣請獨立的子代理只看規範寫，不要看過產出再改題目。
